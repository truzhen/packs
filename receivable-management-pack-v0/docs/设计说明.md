# 应收管理 Pack 设计说明（一页）

- 版本：`scene_pack://receivable-management@0.1.0`，`lifecycle_status = 设计中`
- 归属：G4/G5 W-C（应收域）。os 侧配套：05 层账龄读模型 + 10 层催办策略 + 集成 E2E（另行实现，不在本仓）。
- 上游设计卡：truzhenos 仓 `docs/plans/g4-wc-receivable-pack-design-20260902.md`（本荚为其工作包 ③ 的 packs 侧产物）。

## 1. 这个荚解决什么

一笔应收从"看见逾期"到"发出一条合规的催办消息"之间，真正难的不是写文案，而是：账龄事实必须来自真实单据快照、催办必须受时段与频次约束、话术必须落在白名单内且不触碰禁用措辞、发送必须由人拍板并留下可反查回执。本荚把这条链路声明成受主权门控的流程资产。

## 2. 边界（Pack 只声明，不执行）

| 事项 | 归属 |
|---|---|
| 账龄事实（Sales Invoice 只读快照解析、分桶、客户汇总） | os 05 层读模型 |
| 催办草稿组装与策略裁剪（时段 / 频次 / 白名单 / 禁用词） | os 10 层沟通网关催办策略 |
| 发送裁定（五要素确认、`decision_ref` 签发、单次消费） | Owner + os 01 Base Gate |
| 发送执行与回执 | os 既有受控外发链路 + 03 回执账本 |
| 流程、角色、能力引用、知识、治理声明 | **本荚** |

## 3. 判人 / 判事

- 判人（`person_strategy`）：`receivable_advisor` 是唯一 Proposer 角色，只出催办优先级与话术建议；`dunning_message_send_confirm` / `payment_plan_change_confirm` / `invoice_write_candidate_confirm` / `formal_memory_confirm` 四个高风险动作一律回 Owner + Base Gate；`delegation_allowed = false`。
- 判事（`formalization_requirement`）：巡检、建议、草稿全程候选态；只有对外发送、付款计划变更、单据写回、正式记忆入库才正式化，并产可在 03 反查的 Receipt。

## 4. 流程节点与门

`start → aging_inspection(task/task_governance) → advisor_advice(advice/model, slot_ref=receivable_advisor) → dunning_draft(communication/communication_gateway, gate_policy=base_send_gate, candidate_type=CommunicationDraftCandidate, dangerous_permissions=[external_message_send]) → owner_approval(human_approval, gate_policy=sovereign_gate) → end | close_rejected`

- 危险权限（对外发送）只出现在带 `gate_policy` 的沟通节点上，并且必须穿过 `human_approval` 才可能进入真实外发；不存在从草稿直达执行的边。
- `dunning_draft.params.blocked_outcomes` 声明了五种诚实阻断口径（时段 / 频次触顶 / 频次不可知 / 非白名单模板 / 禁用词否决），阻断态仍是候选。

## 5. 知识与硬约束的关系

`knowledge/dunning/` 三份文件（话术模板集、禁用词表、作业口径 SOP）是**知识陈述**：供 os 侧白名单校验与 Owner 复核参考。阈值真相在 os 侧硬编码，Pack 不得反向覆盖；两者不一致时以 os 实现为准并回报修正知识文件。禁用词表按语义等价判定，只增不静默删——删词属降低护城河，须回 Owner。

## 6. 缺口与待裁定

1. 逾期基准日口径：默认 `due_date`，缺失时 `posting_date` 回退并标 `due_basis=posting_date_fallback`；是否改为"过账日 + 固定账期天数"待 Owner 裁定。
2. 频次上限取 2（保守值），待 Owner 确认是否放宽到 3。
3. 领域语义 glossary（账龄桶、口径边界、别名）尚未落条目，当前只在 SOP 内陈述，本荚不宣称"语义完整"。
4. 尚无隔离 devserver 装入 / 卸载 E2E 证据。
